### 成交均价的解释边界

如果“随机某时”是交易时段内按时间均匀抽样，其期望更接近**时间等权均价（TWAP思路）**；日成交额除以成交量得到的是**成交量加权均价（VWAP）**，二者不相同。仅有日OHLC数据无法还原随机时点的均价，也不使用最高最低的平均来替代。若供应商只给日VWAP，后续可讨论是否接受它作为日均成交近似。

即使忽略实时数据延迟，仍须保持因果顺序：使用T日完整行情训练特征或产生信号，最早使用T+1日的成交价格；不能使用T日收盘后才完整的数据，再回到T日日内均价成交。此约束属于防止未来信息泄漏，不属于上线时效性要求。

### 本轮费用口径

其他主要交易税费是**按成交额计收的规定费率**，并非每笔固定金额，也不是历史上永久不变。目前沪深普通A股可采用：印花税卖出0.05%，过户费买卖各0.001%；经手费双向0.00341%，证管费双向0.002%。后两项在“万二全佣”假设下已包含，不再重复加收。[上交所股票投资费用说明](https://one.sse.com.cn/onething/gptz/)、[上交所收费一览表](https://www.sse.com.cn/services/tradingservice/charge/ssecharge/)。印花税减半政策自2023年8月28日起实施，历史复原模式需按生效日期调整。[财政部公告](https://www.mof.gov.cn/jrttts/202308/t20230828_3904235.htm)。

暂定研究公式，成交额记为A（元）：

```text
买入费用 = max(A × 0.0002, 5) + A × 0.00001
卖出费用 = max(A × 0.0002, 5) + A × 0.00001 + A × 0.0005
```

例如各买卖10万元，买入费用21元、卖出费用71元，合计92元，未含滑点。若万二为净佣，则需另加经手费和证管费。最低佣金只对佣金部分生效；直接设置Qlib的总费率和 `min_cost=5` 不一定精确等同于以上分项公式，后续实现时处理。

当前可将上述口径作为统一成本情景；历史税费复原与按当前成本比较历史策略，是两种不同实验，正式回测时再标明选择。分红与复权的税前/税后口径待供应商数据确认，不在本轮假定已解决。

## 1. 项目能承担什么

Qlib适合作为这项研究的基础：它已经把数据读取、特征生成、模型训练、选股信号、组合回测和结果记录串起来，而且有现成的中证500示例。主要工作是把示例中的假设替换为自己的市场数据、交易规则和投资目标。

它还不是下载后就能连接个人券商账户自动交易的成品。代码中的 `Exchange`、`SimulatorExecutor` 主要服务于模拟交易；Online Serving管理模型和预测更新。真实账户的委托、撤单、成交回报、可卖持仓、资金核对和故障处理需要另行接入。

```text
行情 / 历史成分 / 证券状态 / 复权资料
                  ↓ 自行采购或采集、清洗、校验
Qlib数据目录 → 特征与标签 → 按时间训练、验证 → 每日股票分数
                                                   ↓
                              持仓规则 + 资金约束 + 风控
                                                   ↓
                              模拟成交 → 扣费净值、风险报告
                                                   ↓ 后续另行建设
                              每日候选单 / 模拟盘 / 券商执行
```

这里的“留白”分为三类：**配置选择**（已有能力，需要填参数）、**数据补充**（框架有接口，但内容需提供）、**定制实现**（默认行为不足，需要写逻辑）。不能把“有一个默认值”理解成“已经替你做过正确决策”。

## 3. 先把“两三天”拆开

| 概念 | 例子 | 需要调整的位置 |
| --- | --- | --- |
| 数据频率 | 每天一根日线 | DataHandler和数据源保持 `day` |
| 预测期限 | 预测买入后2或3个交易日的收益 | `label`表达式 |
| 决策频率 | 每日收盘打分 | 信号生成流程 |
| 调仓频率 | 每日交易，或每3个交易日交易一次 | 策略日历/调仓逻辑 |
| 单笔持有期 | 每笔买入后到期卖出 | 持仓批次、退出和延期卖出逻辑 |
| 重训频率 | 每月重训一次 | 滚动任务或Online Manager |

建议先采用可解释的研究时序：**T日收盘数据齐备后计算信号，T+1执行，持仓和净值每天更新**。成交采用开盘、收盘还是某一时段均价，需与你能实际操作的时间一致。

以“收盘至收盘”定义持有期时，标签可以表达为：

- 买入T+1收盘、卖出T+3收盘，跨两个交易日区间：`Ref($close,-3)/Ref($close,-1)-1`。
- 买入T+1收盘、卖出T+4收盘，跨三个交易日区间：`Ref($close,-4)/Ref($close,-1)-1`。

以上只是标签定义，不会自动让策略按时退出。若改为开盘买入，标签分母及退出时刻也须相应修改，并满足可卖规则。所有T+n均指交易日，不是自然日。

`hold_thresh=3`只限制“至少持有若干交易步后才能卖”，不是“第3天必须卖”；每日Topk换仓、每3日整体调仓、每日投入三分之一资金且三日后退出，是三个不同策略。固定期限方案需要考虑同一股票连续入选时各批次的可卖数量以及被迫延期持有。

## 5. 需要的数据：先准备哪些，哪些可以后补

### 5.1 能运行研究流程的最小数据

| 数据 | 字段或内容 | 用途与注意点 |
| --- | --- | --- |
| 日交易日历 | 完整交易日序列 | 标签移动、滚动窗口、调仓排程；覆盖整个研究期 |
| 证券基础资料 | 代码、交易所、上市/退市日期 | 对齐证券身份；保留历史退市和调出证券 |
| 历史中证500成员 | 证券、加入生效日、退出生效日 | 每一天用当时股票池，不能用今天的500只回测全部历史 |
| 日行情 | 原始open/high/low/close、volume、amount、前收参考价 | 生成特征、收益和交易限制；明确股/手、元/千元等单位 |
| 复权资料 | 复权因子、分红送转/配股等事件或供应商说明 | 构建连续价格；复权价和真实委托价格分离 |
| VWAP | 与成交量单位一致的成交额/成交量，或供应商字段 | 默认Alpha158含VWAP；只提供OHLCV并不完整，不能无说明地用收盘价替代 |
| 日涨跌幅 | 与参考价和除权规则一致的 `change` | 默认Exchange使用；不要简单拿不复权价格相除跨除权日计算 |
| 基准行情 | 中证500历史指数序列 | 对应Qlib示例 `SH000905`，实际代码需映射 |

历史长度的研究建议：争取约8—10年的可用日线，覆盖不同市场阶段；数据不足可以先做流程验证。特征首个有效日之前还要预留至少60个交易日左右的预热数据。标签末端需要未来交易日数据，最新尚未到期的标签不能用于训练。

### 5.2 要让A股回测可信，必须进一步补齐

| 数据 | 为什么需要 |
| --- | --- |
| 逐日停复牌、交易状态 | 识别真实停牌与数据漏采。停牌日不能前向填充成可交易日 |
| 逐日涨停价、跌停价及适用规则 | 避免统一9.5%阈值误判；规则随证券、板块和历史日期变化 |
| 历史ST/风险警示、上市阶段、板块信息 | 做当时可知的过滤和规则映射，不能拿今天的状态回填过去 |
| 实际交易费用表及生效区间 | 两三天的周转对费用敏感；历史和当前费用不能一律照抄示例 |
| 退市、长期停牌、公司行动处理信息 | 被动无法退出的股票仍影响资产，不能直接从组合里消失 |
| 行业分类和市值/流通市值历史 | 如需行业上限、风格暴露分析或中性化，则是必要输入 |
| 数据可用时刻、来源和版本 | 证明信号只用了决策时点已经取得的信息，并支持复现 |

日线不足以精确判断开盘时能否成交、封板排队和部分成交。第一阶段可明确采用保守撮合；需要验证具体时段成交时再补分钟线或更细数据。用当日全天成交量或收盘涨跌停状态限制“当日开盘决策”，可能混入当时未知信息；应分离事前决策数据与事后成交模拟数据。

### 5.3 取决于后续目标的数据

- **指数增强**：历史指数权重、行业/风格暴露、因子协方差和个股特异风险。仅在中证500中选股并不要求一开始就购买全套风险模型。项目的指数增强示例使用CSI300，并明确说明示例权重是人工构造的，不能直接视为真实CSI500权重。
- **基本面选股**：财务指标、报告期、实际披露时间及更正版本。Qlib有PIT（按当时可知信息查询）机制和采集示例，但不是完整可直接使用的财务数据库。
- **估值/资金/事件特征**：PE、PB、换手率、股本、公告等；按研究假设逐项增加，不必起步时全部收集。
- **实盘**：真实现金、总持仓、可卖持仓、未完成委托、成交与费用回报；开盘等实时执行还需对应时点行情。

```text
                  volume_shares, amount_yuan, prev_close_reference, adj_factor
instrument:       symbol, exchange, board, list_date, delist_date
universe_history: index_code, symbol, effective_from, effective_to, announced_at
daily_status:     date, symbol, suspended, risk_warning, limit_up_raw, limit_down_raw
benchmark:        date, index_code, close, return_type
fee_schedule:     effective_from, effective_to, side, fee_type, rate, minimum
```

这是接入层建议，不是Qlib强制表结构；需另附字段口径、时区、有效区间是否含端点、来源版本及采集时间。行业、财务、分钟行情按需另表存储。

## 6. 数据如何进入Qlib

本项目已有 `scripts/data_collector/`、`scripts/dump_bin.py`（CSV/Parquet转换）和 `scripts/check_data_health.py`（基础健康检查）。但转换工具不替你完成供应商字段解释、历史修订管理和经济含义校验。

典型目标结构：

```text
cn_data/
  calendars/day.txt
  instruments/all.txt
  instruments/csi500.txt
  features/sh600xxx/open.day.bin
  features/sh600xxx/close.day.bin
  features/sh600xxx/volume.day.bin
  features/sh600xxx/factor.day.bin
  ...
```

关键约定：

1. Qlib价格通常为复权/归一化价格；按文档约定 `原始价格 = Qlib价格 / factor`。供应商的“复权因子”未必可以原样当作这里的 `factor`。
2. 价量口径须匹配，通常价格乘转换因子、成交量除以转换因子，保持成交金额尺度一致。VWAP也必须使用相同价格尺度。
3. `factor`缺失时，Exchange可能进入复权价交易模式并停用整手取整；这会扭曲小资金策略的可买数量。
4. 停牌在Qlib行情层按缺失处理；估值如何沿用历史价格是另一个问题，不能为了估值把停牌恢复为可交易。
5. `csi500.txt`要表达成员历史有效区间；行情需覆盖历史成员并保留退出后的持仓估值和退出所需日期，而不是只下载现在的成员。
6. 先保留原始数据，再生成Qlib派生数据。历史修订、复权尺度改变后不能只盲目追加，必要时重建受影响区间、缓存与预测。

源码README提示官方数据集临时停用，并给出社区源；也提示公共采集数据可能不完善。这是仓库文档状态，本次没有验证下载链接和社区数据的当前覆盖、更新时间或质量。其用途应先限定为跑通流程；正式研究的数据源要单独验收。

数据供应商的选择先看：历史成员与退市覆盖、状态与涨跌停字段、复权口径、更新稳定性、价格和许可。当前不宜在不了解预算和已有渠道的情况下替你定供应商。

## 7. A股适配最容易出现的误差

**交易制度要有生效日期。** 不应写死“所有股票10%、ST永远5%”。交易所已发布2026年修订规则，历史回测须匹配当时制度；具体板块、特殊阶段和实施安排仍需按规则原文核对。[上交所交易规则（2026年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[深交所交易规则（2026年修订）发布通知](https://investor.szse.cn/lawrules/rule/trade/t20260424_620190.html)。

**持仓年龄不等于完整的可卖库存管理。** 普通A股策略需核对T+1可卖约束；一旦连续加仓或分批持有，必须区分旧仓与当日新增仓。`hold_thresh`只提供策略层最小持有步数限制，不足以替代真实账户的可卖数量。

**100股不是可覆盖所有板块和卖出场景的通用订单规则。** Qlib中国市场默认交易单位是100；最终要按纳入板块的申报数量规则和零股卖出规则适配。

**涨停、跌停存在买卖方向差异。** 默认Topk的 `forbid_all_trade_at_limit=True` 会双向禁止触及限制的交易，是简化且偏保守的假设。改成允许某个方向，也不意味着排队必然成交。

**费用必须拆清楚。** 示例买卖成本不等同于税率。2023年8月28日起证券交易印花税实施减半征收，跨这一日期的研究不能假设制度未变；券商最低佣金及规费是否包含在报价内应按合同核对，避免重复计费。[财政部公告](https://www.mof.gov.cn/jrttts/202308/t20230828_3904235.htm)。

**预测相关性不等于可交易利润。** 即便IC为正，频繁换仓、最低佣金、滑点和无法成交也可能消耗收益。策略验收必须基于成本后组合结果。

## 8. 研究设计还要填什么

第一版优先使用Alpha158 + LightGBM，外加一个简单排名规则或线性模型作为对照。这是降低排查复杂度的工程起点，不是模型收益推荐。

- **时间验证**：按时间切分训练、验证、最终测试，不能随机拆股票日记录。验证集用于调参，最终测试期保留到决策完成之后。
- **标签跨界**：例如T+4才结束的标签，在切分边界必须剔除未成熟样本。`RollingGen.trunc_days`提供截断入口，但值和实际切分效果需按标签最大未来偏移核对，不能只按“持有3天”机械填3。
- **滚动更新**：框架支持滑动/扩展训练窗口；重训周期可先设一个固定研究假设，再在验证集比较，不必每天重训。
- **基准口径**：至少看中证500及简单可实现对照；明确价格指数或全收益指数，并确保组合分红处理与基准可比较。
- **指标**：成本后年化收益、最大回撤、波动、超额收益及其稳定性、换手、持有期分布、持仓数、现金比例、费用占比、未成交情况；IC/Rank IC作为信号诊断。
- **统计口径**：即使3日调仓，日净值仍按日频统计。重叠的2/3日标签存在自相关，不能当作相互独立的每日观测夸大显著性。
- **稳健性**：分年度/市场阶段展示结果，测试费用与滑点上升时表现；不能只挑最好的一组参数或一次回测。

模型分数是否有效、策略是否可执行、实际净收益是否满足你的目标，应分别验证。

## 9. 建议实施顺序与每步交付

| 阶段 | 做什么 | 交付/完成条件 |
| --- | --- | --- |
| 1. 明确研究口径 | 确认“两三天”、资金、执行时点、股票权限与目标 | 一份固定的研究配置说明 |
| 2. 数据盘点与验收 | 先抽样，再覆盖全历史成员；核验复权、停牌、成员变更与数据尾部 | 数据字段字典、覆盖报告和异常样例 |
| 3. 基线跑通 | 独立配置文件，使用Alpha158 + LightGBM | 能复现预测、持仓、交易、费用和日净值 |
| 4. 改造真实交易假设 | 2/3日时序、资金、规则、费用和容量约束 | 抽查交易日历、T+1、涨跌停、停牌延期退出等案例 |
| 5. 样本外评估 | 滚动验证、保留测试、成本压力测试 | 可据以决定继续、修改或放弃的报告 |
| 范围外：日常模拟运行 | 每日更新、生成候选单、跟踪真实可成交性 | 数据、信号和交易偏差可追踪，再决定是否接实盘 |

阶段3的“跑通”不等于阶段5的“有效”。目前不需要先引入复杂深度学习、强化学习或自动因子挖掘。
