# 个人研究工作流：实验、模型与策略生命周期

状态：生效设计合同，版本1.1，2026-09-27修订（初始生效2026-09-26）。关联 U23/U26、RUN01—03、DATA01—06、ARC10—12。已有research_lifecycle.py纯对象与接口草案，持久化仓储/API和完整研究闭环未实现；执行保护已有部分实现，A41因SR01—03重新打开。实际缺口见 [IMPLEMENTATION](IMPLEMENTATION.md)。

## 1. 产品目标与范围

产品目标：个人使用的量化工作台支持训练、因子研究、研究分析、回测，并逐步支持前瞻模拟和自动交易。首个研究闭环限定为单人、本地、A股现金股票、日频；具体供应商、股票池和账户参数仍按已有配置与确认状态处理，不把演示参数升级为用户要求。

主流程：建立实验 → 冻结输入与验证方案 → 训练/生成因子 → 样本外评价 → 回测比较 → 保存候选策略 → 前瞻模拟。历史结果导入仍是独立入口，缺证据的对象可浏览，但不能据此晋级为已验证模型或策略。

首个端到端验收目标：用户能用一份冻结的真实数据完成研究，保存模型和策略版本，说明继续验证的依据，并在后续新增数据上跟踪表现。真实数据接入与模型复用优先于第二数据库、多用户、通用插件市场；既有要求和阶段验收仍保留。

## 2. 对象与关联（LIFE01）

| 对象 | 责任与身份 |
| --- | --- |
| Experiment | 研究主题容器；容纳多个实验定义版本与试验记录，不充当一次进程 |
| ExperimentDefinitionRevision | 不可变实验定义：数据快照、历史股票池、特征/因子版本、标签及时间语义、预处理与拟合范围、模型配置、验证方案、组合规则、执行与评估情景、种子与代码/依赖身份；预算由Attempt单独引用执行政策版本 |
| Run / Stage | Run 引用具体实验定义版本；Stage 声明输入、输出及依赖，可表达训练、预测、回测、评价；初期只需固定流程，不要求通用DAG编辑器 |
| Attempt | 一次固定工作流的执行尝试，属于且仅属于一个Run；可包含多个Stage的执行证据。重试与重新实验按下方身份规则区分，历史未记录关联保持unknown |
| ModelArtifactVersion | 不可变模型产物清单：模型、拟合后的预处理状态、特征顺序/类型/单位、标签、训练数据及区间、验证方案、代码/环境身份、种子、产物摘要与来源 Run/Attempt |
| StrategyVersion | 不可变候选策略：信号生成、模型/因子版本、组合与调仓规则、风险约束和执行假设；允许无训练模型的规则策略，不强制依赖 ModelArtifactVersion |
| TrialLedger | 同一研究搜索范围内的全部候选、配置差异、失败/淘汰/选中状态、关联运行、测试集访问和选择理由；统计规则见 [VALIDATION](VALIDATION.md) |
| ResultRevision / ValidationReport | 结果与验证证据各自锁定输入版本；报告带计算定义/分析器版本、样本范围、产物引用与限制，不因新查询自动替换历史结论 |

所有版本用不透明身份与内容摘要定位；名称、展示标签和当前配置路径不能代替版本。比较合同中的 `experiment_id` 是实验变量摘要，不等于 Experiment 容器ID或 Run ID。

### 最小身份、引用和重试合同

- 新建执行命令在启动前分配Run/Attempt身份，导入器将输出绑定该Run及Stage执行证据，并记录外部身份映射；不能再按外部ID创建另一个无关联Run。独立历史导入仍保留原导入身份。
- 新建平台对象必填：不透明ID、schema_version、created_at及来源；不可变版本另含content_digest与父对象ID。引用必须携带确切版本ID，不能只存名称或latest；历史导入缺引用时显式unknown，不据此补造新实体。
- Experiment与定义版本为1:N，定义版本与Run为1:N，Run与Attempt为1:N。一个Attempt覆盖一次固定流程；Stage是定义节点，执行证据以 `(attempt_id, stage_id)` 定位，包含输入/输出引用与状态。首版不支持单Stage断点续跑；重试从固定流程起点重新执行，允许复用定义中显式指定的模型产物。
- 同一Run同时最多一个活动Attempt；只有failed/cancelled/interrupted后才允许对该Run重试；interrupted未核清旧进程已结束前拒绝重试。同有效配置、数据、代码/依赖、种子和模型引用保持不变，增加Attempt序号；成功后再次实验新建Run并复用同定义版本。改变任何上述研究输入须生成或引用相应新定义版本及新Run。仅改变标签/备注不改变定义；执行预算单独保存为Attempt的执行政策修订，不混入模型研究身份。
- Run状态是当前Attempt的投影（按持久化序号而非客户端时间选取）；重试可使Run从failed等状态回到queued，旧Attempt的确认终态不变，失联判定的证据纠正依EXEC02。每个ResultRevision关联产生它的确切Attempt及阶段产物，旧成功结果不能当作新Attempt输出。首版无单Stage续跑；该限制必须显示。
- 提交幂等键与命令有效载荷摘要绑定；同键同载荷复用，同键不同载荷返回冲突，不静默返回另一个实验。验证、幂等占位与Run/Attempt关系须避免重复创建；进程启动失败保留执行器启动失败证据，不伪造进程曾运行。
- ModelArtifactVersion最低输入契约：特征名称/顺序/类型/单位、缺失策略、预处理产物引用、可用时点规则和适用频率；输出契约：预测对象、轴、标签定义与预测期。模型复用核对契约和来源证据，不能仅以文件可加载作为兼容依据。
- StrategyVersion保存训练快照及模型的历史证据，同时保存未来数据输入契约；前瞻每次决策引用当时新产生的数据快照与as_of，不要求永远使用训练快照，也不允许更新旧快照。固定模型首版不自动重训，换模型产生新策略版本。

例如：定义D1 → Run R1/Attempt A1失败 → A2重试成功；再次独立复跑为R2/A3（仍用D1）；更换种子为D2/R3/A4。R1可显示成功，但A1及其失败证据仍可读。

## 3. 执行、复用与晋级

- LIFE02：模型训练与回测可分别执行。同一模型可在不同已声明回测情景中复用而不重新训练；重新拟合模型或预处理器必须产生新模型版本。输入契约不匹配时拒绝预测并说明原因。
- LIFE03：在运行前冻结验证方案并记录实际执行证据，详见 [VALIDATION](VALIDATION.md)。事后诊断、训练实际遵守验证方案、前瞻跟踪三者分别标记。
- LIFE04：候选策略的采用、淘汰、进入前瞻模拟均记录用户决定、理由与关联证据。单个最优指标、Agent接受意见或检查通过不自动触发部署。修改已保存策略的任何有效规则产生新版本；标签和备注可单独修订，不覆盖策略内容。
- LIFE05：前瞻模拟从策略版本冻结之后开始，记录当时可用的数据、预测、目标持仓、模拟订单/成交及账户演进；事后历史回放不称为前瞻。新版本建立新跟踪区间，不拼接成旧版本连续业绩。
- LIFE06：最大并发、任务超时、Agent预算与资源上限的唯一行为合同见 [EXECUTION](EXECUTION.md) EXEC13。必须区分达到调用预算、已运行任务超时与硬资源限制；仅阻止新任务不能满足超时验收。**部分实现（T04；A41因SR01—03重新打开）**：Qlib 与 RD-Agent 两条入口都在容器内运行，内存=`cgroup` 硬上限、CPU=`--ulimit cpu=`、调用预算已有文件原子预留证据，但DB试验预算原子性被SR03反例推翻；超时与失联恢复见SR01/02。被上限终止记 `failed/resource_limit`。证据见 [IMPLEMENTATION](IMPLEMENTATION.md) 的 A41 与 [EXECUTION §5.1](EXECUTION.md) 的容器路线运行手册。

## 4. 交互合同（LIFE07）

- 实验/策略上下文贯穿训练、因子、回测、比较页面；链接携带确切定义、模型及结果版本，跳转不默默改选最新版本。
- 支持保存实验、从旧实验复制为新版本、查看有效参数差异、复用模型及查看样本外证据。当前三个合成入口继续标为集成入口，不能代替上述工作流验收。
- U21统一对象表继续作为全局发现入口；专业页面可提供各自指标与操作，但复用公共身份、筛选和跳转语义，不形成互不相通的对象体系。
- 来源、模拟/真实、关键能力限制与验证状态直接可见；公式、过程和完整证据通过U14说明入口渐进展开。

## 5. 架构边界与实施约束

采用模块化单体与独立引擎进程，不要求微服务。应用层按结果查询/比较、研究编排、分析、执行分责；依赖明确端口。数据目录负责从 DatasetSnapshot 身份解析组件，领域分析不得自行读取当前CN配置来猜历史快照路径。

仓储可共用SQLite事务设施，但结果、执行、因子和数据目录各自定义所需端口；仅拆文件或使用mixin不构成边界验收。CLI/API通过同一组合根组装服务；前端分离数据请求、共享选择状态与专业页面渲染，不要求更换框架。

独立打包不等于脱离仓库运行。引擎运行时、配置与资源路径应由显式部署配置注入；支持的部署方式必须有启动与恢复证据。当前执行器依赖仓库 `scripts/`、约定 `.venv` 与本地配置，迁移尚未实施。

验收统一登记为 IMPLEMENTATION 的 A35—A37、A39-F、A40—A42；旧对象不自动补造关联、升级模型或策略版本，本次无数据库迁移。

## 6. U29/U30数据准备与人参与研究扩展（2026-09-29，仅设计）

新增生效合同[DATA_PIPELINE](DATA_PIPELINE.md)与[HUMAN_RESEARCH](HUMAN_RESEARCH.md)。方向/假设/公式是Experiment内三个独立入口，使用版本化输入、评议、提案、公式与评价报告；上游交接为新草稿引用，不修改旧产物。固定链中每个入口是独立Run/Attempt；等待人工是工作流投影，不能挂起进程等待回答，仍不支持单Stage断点续跑。

LIFE01扩展：数据准备Run的definition_ref允许DataPipelineDefinitionRevision+冻结plan，workflow_kind=data_prepare且experiment_id=null；其他研究Run仍引用ExperimentDefinitionRevision并属于Experiment。Attempt只属于一个Run的规则不变。共享存储/准入规则见ARCHITECTURE §9；这不把数据任务变成研究回测结果。

TrialLedger的候选身份与Attempt计费单位分开；全部方向/假设/公式分支、失败与保留集访问遵循HR07。自动推进仅到报告，策略采用/前瞻/交易仍受LIFE04及TRADING_BOUNDARY约束。新增业务规则已冻结，物理schema/完整DTO/迁移必须通过ARCHITECTURE §9.3设计门，当前对象草案未包含这些能力。

文字评议的ExperimentDefinitionRevision使用明确的任务类型：direction_review/hypothesis_review允许snapshot_ref与evaluation_protocol_ref为null且标not_required_for_text_review，模型/组合/执行情景字段标not_applicable；不是可用于训练的残缺定义。formula_evaluate开始数值阶段前必须绑定快照、标签及评价协议。数据/协议从null变成已选版本时产生新定义和Run，不能运行中补入。字段可空的范围仅此处明示的文字任务，不放宽训练/回测原合同。
