## 每次工作的必读顺序

1. [Spec治理](SPEC_GOVERNANCE.md)：权威顺序、变更流程、完成门槛和长期保护约束。
2. [核心规范](WORKBENCH_SPEC.md)：需求ID、架构、领域语义、数据/API/UI/存储合同。
3. [实施与验收](IMPLEMENTATION.md)：当前真实实现程度、证据及未完成项。
4. [重要变更记录](CHANGELOG.md)：决策来源、兼容影响、纠正与演进历史。
5. 涉及代码结构/新用例须读[架构与实现交接](ARCHITECTURE.md)，再根据任务阅读下表中的相关专题；来源/能力展示变更必须阅读来源审计。

事实基线：`IMPLEMENTATION.md` 顶部的"当前执行里程碑"是唯一权威状态；历史基线 `58fdeeb3` 及其后的逐批交付列在该处与 [CHANGELOG](CHANGELOG.md)。文档批次不替代功能验收。

下一位执行者先读 [IMPLEMENTATION](IMPLEMENTATION.md) 的顶部状态、“实现者交接入口”及T01—T10，按“下一步”执行；SR01—06已有明确修复判定，后续T06/T07/T10须经过各自详细设计门；验证 v2 的口径/证据见[验证口径](VALIDATION.md) §2A，数据源与替换路径见[数据源清单](DATA_SOURCES.md)。规格0.2.1修订记录见 [交接复审](review-20260927.md)。

## 交付底线

- 先明确或修订规范，再实现语义变化；交付同步实现状态、验证证据及限制。
- 原始记录、模拟行情、手写样本、派生计算、定制检查、Agent意见与规则提示必须区分。
- 未接入、受限、未记录与真实零值必须区分；无证据不得标记完成。
- 保留历史revision、审计结果与纠正记录；重要变化追加CHANGELOG。
- 每次重大修改完成验证后commit并push到用户fork，保存可追溯检查点；见治理规范GOV02。
- Spec尚未同步的实现不计作完成。不得通过删要求、弱化验收或删除能力缺口来迁就实现。

现有代码已覆盖合成训练/回测集成、结果导入/比较、版本化分析、执行入口、容器资源限制与数据目录浏览；能力必须按具体路径和证据声明。分析数据身份、完整执行保护、真实训练验证、持久化生命周期和分块规模尚未通过完整验收；实时行情和券商交易未接入。API/CLI分析默认v1、UI显式v2，不表示所有v2合同已通过。A30及真实研究复验保持开放，不能将研究试点冒充完整闭环。

2026-09-26审查发现的R01—R12已修复，当前验证范围和未完成阶段见修复记录。历史数值核对、这批修复或测试通过均不构成全部spec已完成的证明。

旧架构草案、归档JSON与旧聊天均非当前合同。Schema/OpenAPI与spec有冲突时必须登记并修复，不能选择更宽松的一方。
