# 项目 Spec：长期演进的核心锚点

**维护优先级：最高项目优先级。** 本目录是需求、架构、数据语义、能力声明与验收的权威依据。用户最新明确决定及时纳入spec；代码、测试、UI、临时计划及旧聊天总结不能静默改变已生效要求。详细规则见[Spec治理](SPEC_GOVERNANCE.md)。

核心合同版本：0.1（实施基线）；治理版本：1（2026-09-26生效）。版本表示规范基线，不表示功能已完整交付，也不表示所有默认参数获用户确认。

## 每次工作的必读顺序

1. [Spec治理](SPEC_GOVERNANCE.md)：权威顺序、变更流程、完成门槛和长期保护约束。
2. [核心规范](WORKBENCH_SPEC.md)：需求ID、架构、领域语义、数据/API/UI/存储合同。
3. [实施与验收](IMPLEMENTATION.md)：当前真实实现程度、证据及未完成项。
4. [重要变更记录](CHANGELOG.md)：决策来源、兼容影响、纠正与演进历史。
5. 根据任务阅读下表中的相关专题；来源/能力展示变更必须阅读来源审计。

## 交付底线

- 先明确或修订规范，再实现语义变化；交付同步实现状态、验证证据及限制。
- 原始记录、模拟行情、手写样本、派生计算、定制检查、Agent意见与规则提示必须区分。
- 未接入、受限、未记录与真实零值必须区分；无证据不得标记完成。
- 保留历史revision、审计结果与纠正记录；重要变化追加CHANGELOG。
- 每次重大修改完成验证后commit并push到用户fork，保存可追溯检查点；见治理规范GOV02。
- Spec尚未同步的实现不计作完成。不得通过删要求、弱化验收或删除能力缺口来迁就实现。

当前运行证据包括模拟Qlib训练/回测、只读研究结果及过程、结果导入与比较、SQLite/本地对象存储、CLI/API/UI、当前API进程遥测，界面发起/取消的隔离进程执行（Qlib合成行情、RD-Agent合成情景探针）与持久化Attempt，Qlib执行结果的自动入库与ImportReceipt回执，Attempt级失败率/取消/中断/耗时观测，比较表（U17：一行一指标、红最优绿最劣、跨引擎同情景可排名），界面内说明入口（U14）、历史子tab内滚动折叠（U15）与U16可用性修复。实时行情、正式数据目录、调度与资源上限、RD-Agent结果自动入库、第二数据库与第二真实回测引擎仍未接入。完成状态只以实施文档及对应证据为准。

2026-09-26审查发现的R01—R12已修复，当前验证范围和未完成阶段见修复记录。历史数值核对、这批修复或测试通过均不构成全部spec已完成的证明。

旧架构草案、归档JSON与旧聊天均非当前合同。Schema/OpenAPI与spec有冲突时必须登记并修复，不能选择更宽松的一方。
