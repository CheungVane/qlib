# 项目 Spec：长期演进的核心锚点

**维护优先级：最高项目优先级。** 本目录是需求、架构、数据语义、能力声明与验收的权威依据。用户最新明确决定及时纳入spec；代码、测试、UI、临时计划及旧聊天总结不能静默改变已生效要求。详细规则见[Spec治理](SPEC_GOVERNANCE.md)。

核心合同版本：0.2.1（2026-09-27执行交接复审）；治理版本：2。用户已授权按小里程碑实施并逐项回写spec；风险T01-R与因子T01-F后端已交付，证据与剩余差距集中见IMPLEMENTATION顶部。版本表示规范基线，不表示功能已完整交付，也不表示所有默认参数获用户确认。

## 每次工作的必读顺序

1. [Spec治理](SPEC_GOVERNANCE.md)：权威顺序、变更流程、完成门槛和长期保护约束。

3. [实施与验收](IMPLEMENTATION.md)：当前真实实现程度、证据及未完成项。
4. [重要变更记录](CHANGELOG.md)：决策来源、兼容影响、纠正与演进历史。
5. 根据任务阅读下表中的相关专题；来源/能力展示变更必须阅读来源审计。

下一位执行者先读 [IMPLEMENTATION中的T01—T10](IMPLEMENTATION.md)，从T02继续；任务前置、验收出口与待选择项均在该表。规格0.2.1修订记录见 [交接复审](review-20260927.md)，T01-R/F/U已验收，当前下一步为T02。

## 交付底线

- 先明确或修订规范，再实现语义变化；交付同步实现状态、验证证据及限制。
- 原始记录、模拟行情、手写样本、派生计算、定制检查、Agent意见与规则提示必须区分。
- 未接入、受限、未记录与真实零值必须区分；无证据不得标记完成。
- 保留历史revision、审计结果与纠正记录；重要变化追加CHANGELOG。
- 每次重大修改完成验证后commit并push到用户fork，保存可追溯检查点；见治理规范GOV02。
- Spec尚未同步的实现不计作完成。不得通过删要求、弱化验收或删除能力缺口来迁就实现。

现有代码有合成行情训练/回测、结果导入/比较、因子分析、执行启动/取消及只读研究过程等运行证据，具体状态统一见 [IMPLEMENTATION](IMPLEMENTATION.md)。0.2及0.2.1新增实验/模型/策略生命周期、真实训练验证、分块数据和交易边界尚未实现；风险Sortino/rf/目标收益和因子相似度/距离、NW已在API/CLI版本2纠正（3a8f52b8、50f9f366）；API/CLI默认版本1不变，UI显式请求2；T01/A34已按限定范围验收。其他估计量缺陷和真实研究复验尚未完成，A30保持开放。真实数据目录、实时行情、执行预算与券商交易仍未接入。

2026-09-26审查发现的R01—R12已修复，当前验证范围和未完成阶段见修复记录。历史数值核对、这批修复或测试通过均不构成全部spec已完成的证明。
