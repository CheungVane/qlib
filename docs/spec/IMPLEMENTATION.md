## 阶段 M5：真实扩展与部署

交付按实际选择开展：真实供应商、第二回测引擎、第二存储实现、多用户或云部署。第二存储不仅通过单元测试，还必须通过分页、精度、事务发布、备份恢复的一致性测试。真实第二引擎要用同一份数据情景比较，记录匹配和撮合语义的差异；结果数值不要求与Qlib完全一致。

新增对外访问前验证身份授权、数据源凭据隔离、写操作来源校验和审计。对外部署、供应商付费和券商交易均不由本spec自动授权。

## 防止实施偏移的工作流程

每次修改必须在交付说明里列出：目标阶段、关联要求ID、影响的契约/迁移、验收证据、尚未实现范围。新需求改变语义时，先更新spec并写决策记录；普通实现细节无需用户逐项批准。发现未知业务参数时优先明确标注默认或unknown，不能把猜测写成事实。

核心接口变更同时更新契约、夹具和测试；仅改代码不改spec不算完成。上游更新后至少重跑受影响的适配器验收及现有Qlib演示；没有相关变更不重复全仓库耗时测试。

M2正式验收以M1完成为前提；允许为验证用户流程提前建设明确标记的预览，不提升前置阶段完成状态；M3—M5的阶段状态只能由实际证据更新。M3执行层只提升到“部分”：数据目录、真实数据源与A16/A17仍是缺口，Qlib成功结果已可自动入库并记录回执，RD-Agent入口仍为`manual_import_required`；执行成功与入库状态分开。所有“支持某引擎/数据库/数据源”的声明必须指向具体实现和验收记录，Protocol或JSON配置占位不计作支持。
