# 个人量化工作台：能力与低负担使用审查

日期：2026-09-27。代码核对基线3284a7a5；浏览器只读走查当前127.0.0.1:8765的总览、训练、研究中心、数据、因子、回测，查看首页与回测页实际布局。没有启动训练/Agent、修改数据或重新认证统计。本次不考虑实盘，不删除长期U25。

状态：**产品审查与候选方案**。用户明确的低精力、低负担、无需读代码/spec即可正确操作的目标登记为U27；本文页面方案、新增功能及候选验收尚非全部冻结的实施合同。已有U23/U26、T01—T09和SR01—06继续有效，不能凭本报告提前关闭。

## 1. 判断

当前适合熟悉项目的人查看、排查已有结果，尚不足以让个人仅凭UI稳定完成真实数据上的训练、挖掘、回测。已有价值是来源标记、模拟提示、缺失不补0、比较边界、历史记录折叠与上下文帮助；不足主要在流程闭环、关键选择和异常恢复，不只是视觉排版。

判断是基于界面走查与代码/spec核对的专家审查，不是用户可用性测试结果。没有证据支持“任何用户都可零学习使用”；合理目标是具备基础量化知识的人无需理解项目内部对象、命令或实现细节。标签、样本外、成本等研究概念仍须通过界面说明清楚，不能以自动默认隐去。

## 4. 建议的信息结构与交互

主导航候选：**工作台 / 我的研究 / 数据 / 任务 / 设置**。训练、因子、回测、比较保留为具体研究内的专业视图及快捷入口，不让用户反复在互不关联的页面重新选对象。实时/实盘不占本轮主要导航。此结构是建议，实施前须冻结路由与旧URL兼容。

```mermaid
flowchart LR
  A[新建或复制研究] --> B[选择数据与冻结验证方案]
  B --> C[训练模型]
  B --> D[生成或选择因子]
  C --> E[样本外评价与信号]
  D --> E
  E --> F[组合与成本情景回测]
  F --> G[比较基线并保存决定]
```

三个起点模板：训练模型、挖掘因子、回测已有信号/模型。导入历史结果单独保留，不伪造前面步骤。用户不必懂ExperimentDefinitionRevision、Attempt、ResultRevision的差别；界面用“研究/配置版本/执行次数/报告版本”，高级详情展示原身份。

向导最小步骤：①研究目标与名称；②数据、股票池、区间；③特征/标签/模型或因子；④时间切分/验证与预算；⑤运行摘要。回测路线展示组合与成交/成本设置。模板提供版本化工程默认，用户可见其来源和影响；不把模拟模板默认为真实研究，不把自动选择的最终测试窗口悄悄用于调参。

运行前摘要必须回答：用哪份数据、哪些股票和日期；预测什么；训练/验证/最终测试各是哪段；信号何时可用、何时模拟成交；基准与费用是什么；预计/允许消耗多少资源；缺哪些证据；完成后去哪里看。耗时/价格无可靠估计时写未知，调用次数不得冒充货币成本。

研究详情首屏只承担四件事：当前步骤、结果要点、影响判断的限制、下一步动作。其下再展示图表/比较；公式、完整血缘、原始指标ID/日志可展开。真实/模拟、样本内/样本外、成本口径与未通过的门槛不可折叠隐藏；通用审计说明不必每页重复一整块。

页面持续显示同一研究、配置版本、数据版本和评价窗口；跳到因子/训练/回测仍保留上下文。返回、刷新、关闭浏览器不丢已保存研究或后台任务。修改配置生成新版本；“重试执行”“复制并修改”“原配置重新运行”要说明差别且沿用LIFE01身份规则。

结果状态至少分别表达：执行是否结束、产物是否完整、输入是否可信、验证是否完成。不要用一个绿色“成功/通过”覆盖四种含义。没有完成真实样本外验证就写“尚未验证”，而不是自动评价好坏。保持来源真实，不需要承诺用户无需基本量化知识。

## 5. 低负担使用的候选验收

找一位有基础量化知识、未读本仓库代码/spec的人，只使用UI完成以下任务。旁观者不口头指路；记录完成率、求助、误判、往返次数和耗时。以下为待执行验收场景，本轮没有通过声明；时间指标先测基线，不虚构“3分钟完成”。

| 场景 | 通过条件 |
| --- | --- |
| 首次开始 | 能找到三种研究起点；区分演示与真实；不知道内部ID也能选择可用输入 |
| 运行前理解 | 能复述数据/股票池/切分/标签/费用/预算；缺必要数据不能误启动；默认值来源可见 |
| 训练闭环 | 保存配置、运行、关闭再打开后找到结果；能区分训练分数与样本外分数 |
| 因子挖掘 | 能限定搜索范围和预算；找到失败/淘汰项；缺测/无效统计不会被当作零或显著 |
| 回测复用 | 选择已有模型/信号，只改成本重复回测，界面明确不会重新训练，结果可正确对照 |
| 故障恢复 | 版本不兼容、数据缺失、执行失败、结果未入库分别给准确原因和下一步；无需读日志猜操作 |
| 正确解释结果 | 看见“执行成功”不会误认为策略有效；能识别样本内/外、成本前后与不可比较原因 |
| 一周后回来 | 找到最近研究、知道上次改了什么及为何保留/淘汰；已有事项可确认归档且证据不丢 |
| 窄屏与键盘 | 主要流程可操作，无关键内容截断或仅靠颜色解释；焦点与错误提示可达 |

下一步建议：先完成SR01—06及能力声明一致性/运行版本检查；随后以T05—T07/T09串起一个真实数据基线的上述三条路线，逐条验收；闭环稳定后才加批量搜索与高级分析。不能把T09纯当最后的美化工程：在T06详细设计时就设计用户操作路径和失败态，前后端按同一条纵向流程交付。

## 6. 参考与适用限度

界面评估参考[Nielsen Norman Group可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)中的状态可见、识别优于记忆、预防错误、任务导向帮助；据此判断本项目需降低技术术语和跨页面记忆负担。具体导航及优先级是本次设计判断，不是外部来源认证。

[Qlib官方任务管理文档](https://github.com/microsoft/qlib/blob/main/docs/advanced/task_management.rst)提供任务生成、训练与收集等上游能力参考；是否接入仍须按本项目适配器、身份、预算和验收合同判断，不据此宣布批量或滚动训练已完成。旧QUANT_GAP_SCAN和UX_RESEARCH保留为历史研究材料，不能覆盖本次状态核对或当前IMPLEMENTATION。
