# 前瞻模拟与自动交易边界

状态：生效的后续架构约束，尚非可直接实现券商执行的完整合同，版本1.1，2026-09-27修订（初始生效2026-09-26）。关联 U25、LIFE04—06、LIVE01—02、OPS01。当前无券商交易实现；本次文档更新不授权真实下单、付费供应商接入或对外部署。

## 1. 路径与责任（TRADE01）

候选 StrategyVersion → 冻结版本的前瞻模拟 → 有边界的实盘部署。研究系统负责生成与评价候选；交易运行时负责已部署版本的信号、账户、订单与风险控制。可在同一代码库内分模块，交易运行时应与研究任务进程隔离；无需预先建设分布式系统。

研究 Attempt 的成功/失败/取消不能表示委托状态；停止研究进程不代表撤销券商订单。历史回测、确定性回放、前瞻模拟、实盘分别标明模式，不能合并为同一种业绩。

## 2. 核心对象（TRADE02）

| 对象 | 最低语义 |
| --- | --- |
| Deployment | 固定策略版本、账户、运行模式、启停时间、日历/调度、运行环境、风险规则及数据契约；更换策略版本创建部署修订 |
| AccountSnapshot | 券商观测与平台账本分别保留来源/时间；现金、持仓、可卖数量、冻结资金及外部现金流可对账 |
| TargetPortfolio / OrderIntent | 信号证据、目标持仓与调仓意图；意图具有持久化幂等身份和策略/账户归属 |
| Order / Fill | 平台与券商ID、数量/价格精度、提交/确认/部分成交/成交/拒绝/撤单过程；成交事件可去重，未知状态保留待核对 |
| RiskDecision / Reconciliation | 下单前允许或拒绝的规则及依据；账户、委托与成交差异、处理决定及恢复记录 |

账户账本是持续对象，不能靠拼接Run净值反推订单或可用资金；多策略共享账户的资金与持仓归属需另行定义，首个实盘范围不隐含该能力。

## 3. 命令、恢复与风控

- TRADE03：先持久化订单意图再提交；超时意味着结果未知，必须按券商订单/成交证据核对后决定后续动作，不能盲目重发。重复回报幂等处理，部分成交、撤单请求与确认分开。断线恢复后先对账，再恢复新增订单。
- TRADE04：下单前验证账户权限、资金、可卖数量、证券状态、行情新鲜度、单笔/总敞口等已配置约束。缺关键输入时阻止新增风险；阈值必须有来源和有效配置，不在文档中虚构账户参数。回撤阈值是控制规则，不保证跳空行情下守住损失上限。
- TRADE05：暂停新增订单、请求撤销未完成订单、主动平仓是三类独立操作；紧急停止的具体动作必须可配置、明确展示并记录结果，不能把进程退出作为完成证据。研究系统故障不应改写已有委托事实。
- TRADE06：重启核对账户、委托、成交与部署状态，保留审计记录；凭据留在交易适配层。实盘接入前，按当时选定券商、账户、市场核对接口与适用要求，不沿用历史规则审计当作现行认证。

## 4. 后续交付门槛

先验收前瞻模拟，再对明确选择的券商与账户定义实盘接口和运行方案。验收必须覆盖提交后超时、重复成交回报、部分成交与撤单竞争、重启/断线、账户差异、数据陈旧和紧急停止；同时核对资金/持仓守恒与重复订单风险。

执行前设计门：后续实施者先补齐订单状态/合法迁移表、超时后的查询与重发裁决、账户冻结/解冻和结算账目、精度/手续费、紧急停止与人工恢复策略、历史规则/时间语义及事件幂等键；用具体事件序列手工走通，并将决定、模拟夹具及预期账目登记到本专题后才实施。上述业务设计不可自行留给券商SDK默认行为；普通技术方案无需重复请求用户许可，券商/账户/实盘权限等未知选择按DEC02处理。

设计门不算功能通过；功能验收拆成IMPLEMENTATION的A39-F（前瞻）、A39-R（模拟订单与恢复）、A39-L（真实券商），分别有证据，父项A39在全部子项通过前保持未完成。本次没有新增执行入口、自动晋级、真实账户或下单授权；不得将本文件登记为已支持自动交易。
